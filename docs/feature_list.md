# Functional requirements (IEEE-style SRS §3.2)

Virasat is a responsive Django website, not a native mobile application. Each row states a testable input, processing step, output and error handling observed in the code. Paths refer to `virasat_project/`.

| ID / actor and requirement | Inputs | Processing | Output | Errors / restrictions |
| --- | --- | --- | --- | --- |
| FR-1 Visitor: view home and impact (`core/views.py`) | GET `/`, `/impact/` | Read published products and aggregate real database totals | Featured craft cards and impact numbers | Empty products or sales show friendly text/zero |
| FR-2 Visitor: browse crafts (`catalog/views.py`) | GET craft/category slug | Retrieve matching published products | Craft/category page | Unknown slug → 404 |
| FR-3 Visitor: search and filter (`catalog/forms.py`, `catalog/views.py`) | GET search, category, craft, state, prices, verified flag | Validate filters and query product ORM | 12-item pages, sort and kept query string | Invalid range shows form error; no results show clear-filter link |
| FR-4 Visitor: view product (`catalog/views.py`) | GET numeric ID and title slug | Restrict unpublished products to owner, count valid visit | Catalog story, care, maker, rating | Wrong slug → permanent redirect; inaccessible product → 404 |
| FR-5 Visitor: remember language and visits (`core/views.py`, `catalog/views.py`) | GET language, product ID | Set `lang`/`recently_viewed` cookies | Hindi description when available, recent strip | Unsafe referrer returns home; bad IDs ignored |
| FR-6 Visitor: register (`accounts/forms.py`, `accounts/views.py`) | POST username, passwords, artisan/buyer role, phone, state, city | Validate, create User/Profile, add Group, log in | Home redirect and welcome message | Duplicate username, weak password, invalid role/phone show form errors |
| FR-7 User: sign in (`accounts/views.py`) | POST credentials, optional remember flag and next path | Authenticate, set browser or two-week session expiry | Safe local redirect | Wrong credentials show form errors; external `next` ignored |
| FR-8 User: sign out (`accounts/views.py`) | POST logout form with CSRF | Clear login session | Login-page redirect | GET → 405; missing CSRF → styled 403 |
| FR-9 User: edit own profile (`accounts/forms.py`) | POST contact details and optional image | Validate 10-digit phone and JPG/PNG/WebP ≤2 MB | Saved profile and redirect | Another user's profile not accessible; bad upload shows error |
| FR-10 Visitor: view artisan (`accounts/views.py`) | GET artisan User ID | Find artisan role and published products | Public biography and verified badge | Buyer ID → 404; drafts not displayed |
| FR-11 Buyer: save a product (`catalog/views.py`) | POST product ID | Toggle unique Wishlist record | Updated saved products | Nonbuyer → 403; unpublished ID → 404 |
| FR-12 Buyer: review a delivery (`catalog/views.py`) | POST rating (1 to 5), optional comment | Verify delivered OrderItem; create unique Review | Review shown on product page | Not delivered → 404; duplicate shows message; invalid rating rejected |
| FR-13 Artisan: start catalog (`catalog/forms.py`, `catalog/views.py`) | POST craft, category, notes, title hint, price, stock, photo | Validate image/text/price; generate a draft | Private Product and edit-page redirect | Invalid form → styled form with errors; no automatic publication |
| FR-14 Artisan: generate optional AI text (`catalog/ai_service.py`) | Craft facts and optional server API key | Call provider at most 15 times/session/day, or deterministic offline fallback | Editable English, Hindi, story, care, tags and source label | Timeout/bad JSON/no key/cap → fallback; key never logged |
| FR-15 Artisan: edit and publish (`catalog/views.py`) | POST own product fields and save/publish action | Compare generated text, mark edited, save status | Updated draft or published detail | Nonowner → 404; invalid image/price/notes shows errors |
| FR-16 Artisan: manage lifecycle (`catalog/views.py`) | POST publish/archive/draft; GET+POST delete; confirmed regenerate | Check owner, stock/form validity and historical order references | Updated status, new draft, or deleted item | Ordered product cannot delete; regeneration returns to draft |
| FR-17 Buyer: manage session cart (`orders/cart.py`) | POST product ID and quantity | Store `{id: quantity}`, cap live stock, one product query for lines | Cart page, total and count badge | Invalid quantity → 400; unavailable item removed with message |
| FR-18 Buyer: check out (`orders/views.py`) | POST delivery fields and COD/UPI-demo choice | Validate, atomically check/decrement stock, snapshot prices, create Order/Items | Buyer order page and VR invoice number | Stock race → rollback and cart notice; UPI demo moves no money |
| FR-19 Buyer: view own orders/invoice (`orders/views.py`) | GET own VR-numbered order | Owner-filter Order and related items | Timeline and downloadable plain text | Other buyer's order/invoice → 404 |
| FR-20 Buyer: cancel placed item (`orders/views.py`) | POST own OrderItem ID | Atomically mark cancelled, restore stock and reduce amount due | Updated order and message | Wrong owner → 404; not placed → styled 403 |
| FR-21 Artisan: fulfil own items (`orders/views.py`) | POST next delivery stage | Check product artisan; advance placed→confirmed→shipped→delivered | Updated artisan order and fair-pay amounts | Wrong owner → 404; skipped/backward status rejected |
| FR-22 Buyer: post request (`linkage/forms.py`) | POST idea, category/craft, quantity, budgets, needed date | Validate budget and future date, save BuyerRequest | Open request and redirect | Wrong role → 403; invalid date/budget shows form errors |
| FR-23 Artisan: find work (`linkage/matching.py`) | GET artisan's own product categories/crafts and profile state | Annotate category +2, craft +2, state +1; order open matches | Scored request list | No matches → friendly empty state |
| FR-24 Artisan: quote a request (`linkage/views.py`) | POST price, 1 to 90 days, message | Check open request and unique artisan/request pair | Pending Proposal and redirect | Duplicate surfaced on form; closed request → 404 |
| FR-25 Buyer: accept/reject/close (`linkage/views.py`) | POST proposal/request ID | Check ownership; atomic accept rejects other pending offers and closes request | Updated statuses and messages | Wrong owner → 404; missing/closed item not accepted |
| FR-26 Verifier: moderate artisans (`accounts/views.py`) | GET queue; POST approve/reject | Check `accounts.can_verify_artisan`; approve records verifier/time; reject records status | Updated verification queue | No permission → custom 403; nonpending artisan → 404 |
| FR-27 Admin: maintain data (`*/admin.py`) | Staff admin forms/action | Django Admin filters/search/inlines and artisan verification action | Edited database records | Django staff/model permission checks |
| FR-28 Developer: populate demo (`catalog/management/commands/seed_demo.py`) | `manage.py seed_demo` in development | Idempotent groups, users, crafts, artwork, orders and offers | Local 5-minute demonstration data | Refuses `DEBUG=False` because public demo password is unsafe |
| FR-29 Developer: generate original artwork (`catalog/art.py`) | Product slug, craft, title and optional owned seed photo | Seeded Pillow patterns and item silhouettes; crop local photos to 4:5 | 1200 x 1500 product JPEG below 250 KB and 800 x 800 craft cover | No downloaded images; existing files change only with `--refresh-images` |

These are functional requirements, not performance guarantees or an assertion that payments, native installation or external AI access are available on the hosting platform.
